# My Home Assistant Wiki

Локальный сайт заметок о Home Assistant. Материалы взяты из Obsidian, а большая HA wiki разделена на самостоятельные темы. Оригиналы в Obsidian не изменяются.

## Запуск

На этом Mac: `./start.command` из папки проекта. Скрипт использует установленный Node.js или runtime Codex. Открыть http://127.0.0.1:4173. Остановить сервер: Ctrl+C.

На другом компьютере нужен Node.js 20+:

```sh
npm ci
npm start
```

Сервер слушает только 127.0.0.1. После редактирования выполнить `npm run build` и обновить страницу.

## Организация

- `content/*.md` — подготовленные для сайта статьи.
- `content/catalog.json` — категории, названия, описания и статусы.
- `content/site.json` — подписи статусов и состав списка HACS и перенаправления объединённых страниц.
- `content/wiki-redirects.json` — переходы со старых якорей HA wiki на новые страницы.
- `assets/` — стили, поиск, тема и фильтры.
- `build.mjs` — сборка HTML в `dist/`.
- `render-note.mjs` — Markdown, оглавление, wikilinks и callout-блоки.
- `archive/before-organization/` — полная wiki и каталог до разделения, а также карта исходных строк каждой темы.
- `archive/demo-content/` — первоначальные примеры; на сайт не попадают.

Установка HACS, интеграции, карточки, Firefox и OpenSpeedTest находятся в категории HACS. В боковом меню этой категории только «Установка HACS» и «Полезные дополнения»; порядок и видимость задаёт `navigationIds` в каталоге, а `navigationParentId` задаёт активный пункт для отдельных дополнений. Отдельные статьи доступны из списка дополнений и поиска. Страница «Начало» собирает только статьи категории «Основы Home Assistant», в том числе вложенное дерево «Отопление · Rinnai». Шаги одной инструкции не разнесены по разным страницам.

## Статусы

В каталоге каждая статья содержит поле `status`:

- `verified` — зелёный «Проверено».
- `needs-test` — оранжевый «Нужно проверить».

Первоначальное распределение: галка ✅ перед заголовком исходной wiki означает `verified`; отсутствие галки — `needs-test`. В отдельных импортированных заметках статус по умолчанию `needs-test`, кроме SMTP, на который ведёт отмеченная галкой тема wiki. Статус отражает отметку владельца, а не техническую проверку агентом. Поле `statusSource` сохраняет основание выбора. Для HIBP, сброса пароля, BLE-C600, ONVIF и Ezviz владелец подтвердил статус «Проверено» (`owner-confirmed`). Техническое содержание инструкций не перепроверялось.

## Добавление заметки

1. Создать файл в `content/`, например `new-hacs-repo.md`.
2. Добавить запись в `content/catalog.json` в категорию HACS. Указать `id` (имя файла без расширения), `title`, `description`, `status`, `kind: "article"` и сведения об исходнике.
3. Добавить id в `hacsTopicIds` в `content/site.json`, чтобы заметка появилась в списке «Полезные дополнения». Состав «Начала» автоматически берётся из его категории.
4. Выполнить сборку.

Заголовок статьи берётся из каталога. Подразделы в Markdown начинаются с `##`. Поддержаны таблицы, списки, цитаты, выделения `==текст==`, блоки кода, ссылки вида `[[имя заметки]]`, `[[#заголовок]]`, сворачиваемые callout-блоки. Вложения из vault автоматически не переносятся. Произвольный HTML экранируется, кроме `<br>`; HTML внутри YAML показывается как код.

В `scripts/` сохранены одноразовые инструменты импорта и разделения. Не запускайте `organize-wiki.py` повторно после ручных правок: он воспроизводит разбиение из архивного снимка. Общий импорт защищён от перезаписи уже организованного каталога.

## Проверки

После разделения проверены все внутренние ссылки и якоря, переходы со старых якорей wiki, единственный H1 на странице и сохранение исходных блоков кода при разделении; после обезличивания в примерах используются условные значения. В браузере проверены каталоги, теги и фильтр статусов.

## Публикация

`dist/` — обычные статические файлы, подходящие для GitHub Pages. Сборка полностью пересоздаёт эту папку; вручную редактировать её не нужно. На сайт копируются только файлы, включённые в каталог, и необходимые ресурсы. Архивные материалы в сборку не входят.

Репозиторий: https://github.com/OlegKocha/my-ha-wiki

Сайт: https://olegkocha.github.io/my-ha-wiki/

Workflow `.github/workflows/pages.yml` при каждом push в `main` устанавливает зависимости через `npm ci`, запускает тесты и проверку публичных заметок, собирает сайт и публикует только `dist/` в GitHub Pages. Запуск вручную доступен через Actions → Publish GitHub Pages → Run workflow. Источник Pages — GitHub Actions.

Для локальной проверки публикуемой версии: `SITE_ENV=production npm run build`. Ссылки и ресурсы относительные, поэтому сайт работает в подпапке `/my-ha-wiki/`.

Логотип в шапке: официальный знак [Home Assistant](https://www.home-assistant.io/images/favicon.svg), сохранён локально в `assets/home-assistant.svg`.

## Чтение и экспорт

Markdown остаётся исходным форматом и доступен по кнопке «Скачать Markdown». На сайте он преобразуется в оформленный текст: заголовки, выделения, ссылки, шаги и заметки. Стрелки в обычном тексте отображаются как →, URL-ссылки получают короткие подписи. Код отображается отдельно с сохранением форматирования. В публичных примерах личные адреса, идентификаторы и учётные данные заменены шаблонами.

Экспорт доступен только в Markdown, в том числе на узких экранах.

## Последние изменения

Главная показывает пять недавно добавленных или изменённых статей. `content/revisions.json` хранит дату первого включения, дату изменения и отпечаток содержимого и метаданных. Сборка обновляет дату только при изменении текста, заголовка, описания, статуса или раздела. Файл нужно сохранять в Git вместе со статьями: свежий checkout и пересборка не меняют порядок. Для ранее существовавших статей начальные даты взяты из времени изменения локальных файлов.

## Личные данные

Публичные копии обезличены: личные DDNS-имена, адреса сети, идентификаторы устройств, названия комнат и явно заданные пароли заменены примерами. Настройки SMTP используют `!secret`, код BLE-C600 — условные сущности `sensor.c600_*`. Публичная ссылка на репозиторий BLE-C600 оставлена по просьбе владельца. Заводской адрес настройки W610 сохранён как техническая информация.

`privacy.mjs` проверяет каждую публикуемую заметку перед сборкой: типичные токены, пароли, адреса почты, частные IP, DDNS, аппаратные идентификаторы и локальные пути. Ошибка сообщает имя файла и категорию, не раскрывая найденное значение. Автоматическая проверка дополняет ручную: новые заметки всё равно следует просматривать перед публикацией.

`archive/` содержит локальные резервные копии, может включать личные данные и исключён из Git через `.gitignore`. Не загружайте его принудительно. Сайт обслуживает только `dist/`, куда попадают выбранные статьи, поиск и ресурсы интерфейса; оригинальные архивы и Obsidian туда не копируются. Старые URL объединённых статей перенаправляют на новые; исходные Markdown удалённых дублей не публикуются.

## Оформление статей

YAML/YML-блоки выводятся как закрытые HTML `details`: их можно раскрыть мышью или клавиатурой даже без JavaScript. Внутри доступно копирование исходного кода. Markdown-экспорт сохраняет обычные fenced code blocks. Другие языки кода остаются раскрытыми.

Проверка рендерера: `npm test` (или `node --test tests/*.test.mjs`).

## Мобильные экраны

До 1024 px навигация открывается отдельным выдвижным меню; все его уровни используют один размер шрифта. На главной разделы изначально свёрнуты, в статье раскрывается текущий раздел. Учтены safe-area, динамическая высота экрана и экранная клавиатура в поиске. Оглавление доступно над текстом, таблицы и код прокручиваются внутри собственных блоков.
