Сетевой координатор подключается к Zigbee2MQTT по TCP. Zigbee2MQTT передаёт устройства в Home Assistant через MQTT. Пробрасывать USB в HA для такого подключения не требуется.

Инструкция подходит для координаторов на **CC2652P / CC2652P7 с прошивкой координатора Z-Stack**, например HamGeek с сетевой прошивкой XZG. Запуск проверен на **Zigbee2MQTT 2.14.3**, **zigbee-herdsman 11.2.0** и Zigbee-прошивке **20240710**. Итог проверки — работающий третий экземпляр, соединение с MQTT и публикация обнаружения в Home Assistant. На момент запуска к нему ещё не было привязано устройств.

## Несколько координаторов в одном Home Assistant

Для каждого координатора нужен свой экземпляр Zigbee2MQTT, каталог данных и MQTT-топик. Один брокер Mosquitto может обслуживать их все. Каждый координатор создаёт отдельную Zigbee-сеть: добавление второго или третьего координатора само по себе не расширяет первую сеть.

| Что разделяем | Второй экземпляр | Третий экземпляр |
|---|---|---|
| Каталог данных `data_path` | `/config/zigbee2mqtt_2` | `/config/zigbee2mqtt_3` |
| MQTT `base_topic` | `zigbee2mqtt_2` | `zigbee2mqtt_3` |
| Адрес координатора, условный пример | `tcp://192.0.2.66:6638` | `tcp://192.0.2.68:6638` |

Уже работающие экземпляры сохраняют свои настройки. Новый экземпляр не должен обращаться к координатору, который занят другим Zigbee2MQTT или ZHA. Для новой сети создаются собственные параметры сети; для переноса существующей сохраняются прежние. [Несколько координаторов с XZG](https://xzg.xyzroe.cc/faq/).

## Подготовить дополнение и файл

1. Подключите координатор к сети и закрепите за ним IP-адрес в роутере. В его веб-интерфейсе проверьте сетевой режим и роль **Coordinator**. Скопируйте `serial.port` и `serial.adapter` из генератора настроек Zigbee2MQTT.
2. Откройте конфигурацию отдельного экземпляра дополнения Zigbee2MQTT. Для примера ниже задайте `data_path: /config/zigbee2mqtt_3`, а в разделе `socat` выключите `enabled`.
3. Остановите этот экземпляр перед редактированием. Создайте каталог `zigbee2mqtt_3` и файл `configuration.yaml` в каталоге конфигурации HA.
4. В **File editor** этот файл может отображаться как `/homeassistant/zigbee2mqtt_3/configuration.yaml`, хотя дополнение использует `/config/zigbee2mqtt_3/configuration.yaml`: приложения видят общий каталог по разным путям. Сверяйте имя папки с `data_path`. Это отдельный файл Zigbee2MQTT, а не основной `configuration.yaml` Home Assistant.

Настройки `mqtt` и `serial`, заполненные на вкладке конфигурации дополнения, могут переопределять одноимённые значения файла. Проверьте, что там нет адреса от другого координатора или старого `base_topic`. Если эти параметры целиком задаются в файле, соответствующие разделы дополнения можно оставить пустыми: `mqtt: {}` и `serial: {}`. [Настройки дополнения и их передача в Zigbee2MQTT](https://github.com/zigbee2mqtt/hassio-zigbee2mqtt/blob/master/common/rootfs/docker-entrypoint.sh).

## Полный YAML для первого запуска новой сети

Ниже — шаблон для **нового координатора без привязанных устройств**. Замените адрес `192.0.2.68` на свой: это условный адрес для документации. Укажите действительные учётные данные MQTT. Адрес `core-mosquitto` подходит для дополнения Mosquitto в HA; для другого брокера нужен его адрес.

[Скачать configuration.yaml для новой сети](assets/examples/zigbee2mqtt-network/configuration.yaml)

```yaml
version: 5

mqtt:
  base_topic: zigbee2mqtt_3
  server: mqtt://core-mosquitto:1883
  user: mqtt_user
  password: REPLACE_WITH_YOUR_MQTT_PASSWORD

serial:
  port: tcp://192.0.2.68:6638
  adapter: zstack

advanced:
  log_level: info
  transmit_power: 20
  pan_id: GENERATE
  ext_pan_id: GENERATE
  channel: 11
  network_key: GENERATE
  last_seen: ISO_8601

homeassistant:
  enabled: true

frontend:
  enabled: true
  port: 8099
```

`version: 5` обозначает версию формата конфигурации. `transmit_power: 20` запрашивает мощность 20 dBm у поддерживающего её адаптера. Для другого оборудования сверяйте допустимые значения с его документацией. Эта строка не обязательна для подключения. [Настройки адаптера](https://www.zigbee2mqtt.io/guide/configuration/adapter-settings.html).

При создании сети Zigbee2MQTT генерирует значения вместо `GENERATE` и сохраняет их в конфигурации. Далее рабочий файл должен содержать **сохранённые `pan_id`, `ext_pan_id` и `network_key`**. Перезапись рабочего файла стартовым шаблоном заново запрашивает генерацию. Смена ключа сети требует повторного сопряжения устройств. [Параметры Zigbee-сети](https://www.zigbee2mqtt.io/guide/configuration/zigbee-network.html).

Не копируйте в свою сеть чужие идентификаторы и ключи. В этой статье нет пароля, ключа сети и адреса реального координатора из исходной настройки.

## Какие ошибки встретились

В этом случае были ошибки формата YAML и рассогласование сохранённого состояния. Оснований считать координатор неисправным или объявлять всё это багом Zigbee2MQTT не появилось.

| Сообщение или симптом | Что выяснилось | Как исправить и избежать |
|---|---|---|
| `homeassistant must be object` | В файле формата 5 осталось старое `homeassistant: true`. | Использовать блок `homeassistant` с вложенным `enabled: true`, как в полном примере. |
| `advanced/log_level must be equal to one of the allowed values` | Значение `warn` не соответствует актуальной схеме. | Указать `info`, `debug`, `warning` или `error`. Для обычной работы удобно `info`. |
| После вставки фрагмента редактор показывает ошибку | Внутри `advanced` появился второй `advanced`, а `log_level` был продублирован. | Добавлять только нужную строку в существующий блок. Использовать пробелы, одинаковые отступы и единственный экземпляр каждого ключа. |
| `network commissioning timed out` | Не завершилось создание сети за отведённое время. Точная причина этого первого тайм-аута не была установлена. | Сохранить полный журнал, проверить параметры и состояние координатора. Упоминание одинаковых PAN ID в ошибке — предположение драйвера, а не подтверждённый конфликт. |
| `Configuration is not consistent with adapter state/backup!` | После `ext_pan_id: GENERATE` новый идентификатор в файле отличался от уже сохранённого в координаторе и его резервной копии. | Согласовать конфигурацию с сохранённым состоянием по инструкции ниже. Не генерировать новые значения при каждом исправлении. |

Из старого примера также убрали `permit_join`, `advanced.availability_blocklist` и `advanced.availability_passlist`: эти параметры удалены из актуального формата. Разрешение на сопряжение включается через интерфейс Zigbee2MQTT. [Миграция настроек](https://github.com/Koenkk/zigbee2mqtt/blob/2.14.3/lib/util/settingsMigration.ts).

Символы `\` в конце строк, `&#x20;` вместо пробелов или `tcp\://` могут появляться при копировании текста из чата. Если они попали в сам файл, удалите их. Правильный адрес начинается с `tcp://`.

## Исправить несовпадение с координатором

В сообщении об ошибке `configured` — значение из конфигурации, а `adapter` — значение в координаторе. Сравните **PAN ID, Extended PAN ID, Network Key и Channel List**. В разобранном случае различался только **Extended PAN ID**. После возврата значения из координатора сеть запустилась с сообщением `resumed`.

1. Остановите нужный экземпляр. Сохраните копию его каталога данных, включая `configuration.yaml`, `database.db` и `coordinator_backup.json`, если эти файлы уже есть.
2. Возьмите **Extended PAN ID именно из поля `adapter` своего журнала**. Журнал выводит его как шестнадцатеричную строку. Например, условному `0123456789abcdef` соответствует массив ниже.
3. Замените существующий `ext_pan_id` вместе со всем его списком чисел **одной строкой** внутри `advanced`:

```yaml
  ext_pan_id: [0x01, 0x23, 0x45, 0x67, 0x89, 0xAB, 0xCD, 0xEF]
```

Это иллюстрация преобразования, а не универсальное значение для всех координаторов. Перед ключом — два пробела, как у `pan_id`. Совпадающие параметры сети сохраняются. Сохраните файл и запустите экземпляр снова. [Разбор ошибки configuration-adapter mismatch](https://www.zigbee2mqtt.io/guide/installation/20_zigbee2mqtt-fails-to-start_crashes-runtime.html).

> [!note] Резервную копию для этого исправления удалять не нужно
> Предложение удалить `coordinator_backup.json` в журнале относится к намеренному пересозданию сети. Это другой сценарий, который может потребовать повторного сопряжения всех устройств. Для сохранения существующей сети сначала согласуйте параметры.

Отсутствие `ext_pan_id` тоже не доказывает конфликт с соседней сетью: в использованном драйвере Z-Stack стандартное значение из восьми `DD` обрабатывается особым образом и заменяется IEEE-адресом адаптера. Поэтому рекомендация «добавить `GENERATE` при любом тайм-ауте» неверна. [Обработка идентификатора в zigbee-herdsman 11.2.0](https://github.com/Koenkk/zigbee-herdsman/blob/v11.2.0/src/adapter/z-stack/adapter/manager.ts).

## Что не является ошибкой и как проверить запуск

`Socat not enabled` нормально для прямого подключения `tcp://…:6638`. Поле сети `8485/tcp` с подписью **Socat tcp-listen port** относится к Socat. Изменение внешнего порта, например на `8487`, не настраивает соединение с координатором.

`8099` в полном YAML — внутренний порт веб-интерфейса дополнения. В отдельных контейнерах он может совпадать. Если вручную публикуете их веб-интерфейсы на одном хосте, внешние порты должны различаться. [Документация дополнения](https://github.com/zigbee2mqtt/hassio-zigbee2mqtt/blob/master/zigbee2mqtt/DOCS.md).

После сохранения файла запустите нужное дополнение и смотрите **новые строки после последнего запуска**, а не старые ошибки выше в журнале. В нашем случае успешный запуск выглядел так:

```text
zigbee-herdsman started (resumed)
Connected to MQTT server
MQTT publish: topic 'zigbee2mqtt_3/bridge/state', payload '{"state":"online"}'
Started frontend on port 8099
Zigbee2MQTT started!
```

`Socket opened` подтверждает только открытое TCP-соединение. О готовности Zigbee2MQTT говорит финальная строка `Zigbee2MQTT started!`. Сообщение `Currently 0 devices are joined` означает, что устройств в этом экземпляре пока нет. После успешного запуска откройте его интерфейс, включите **«Разрешить подключения»** и переведите устройство в режим сопряжения.

Публикация в `homeassistant/…/config` означает, что Zigbee2MQTT отправил сведения для автоматического обнаружения. В HA должна быть включена интеграция **MQTT**, подключённая к тому же брокеру. Появление устройств проверяется в **Настройки → Устройства и службы → MQTT**. [Интеграция с Home Assistant](https://www.zigbee2mqtt.io/guide/usage/integrations/home_assistant.html).

## Мощность transmit_power и её проверка

Параметр находится внутри существующего `advanced`, на одном уровне с `log_level`. Для добавления достаточно одной строки `transmit_power: 20`. Второй блок `advanced` создавать не нужно.

Чтобы проверить отправку настройки, замените существующий `log_level: info` на `log_level: debug`, сохраните файл и перезапустите дополнение. Во вкладке **«Журнал» самого дополнения в HA** найдите команду:

```text
--> SREQ: SYS - stackTune - {"operation":0,"value":20}
```

Она подтверждает запрос мощности 20 dBm. Рядом найдите ответ `SRSP: SYS - stackTune` и проверьте результат операции: одна исходящая команда ещё не подтверждает принятие настройки. В нашем разборе ответ на эту команду не был получен для проверки, поэтому фактическая мощность отдельно не подтверждена. Журнал также не заменяет измерение радиомощности. [Отправка настройки драйвером Z-Stack](https://github.com/Koenkk/zigbee-herdsman/blob/v11.2.0/src/adapter/z-stack/adapter/zStackAdapter.ts).

Debug-сообщения по умолчанию не передаются в веб-интерфейс Zigbee2MQTT — используйте журнал дополнения или файл `log.log`. После проверки верните `log_level: info`. [Настройка журналирования](https://www.zigbee2mqtt.io/guide/configuration/logging.html).
